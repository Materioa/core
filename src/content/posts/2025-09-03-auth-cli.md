## Global Configuration

### Base URLs
- **Production**: `https://materioa.vercel.app/api/v2`
- **Development**: `http://localhost:3000/api/v2`

### Standard Headers
All requests should include:
```
Content-Type: application/json
Authorization: Bearer <JWT_TOKEN>  (for protected endpoints)
```

- **Pro** (`isProUser`): ₹299 lifetime purchase - full feature access

## 1. Signup Endpoint

### Overview
The Signup endpoint creates a new user account by redeeming an invite code. It validates the code, creates the user record, marks the invite as redeemed, and generates a recovery key for emergency account access.

### Endpoint Details
- **URL**: `/signup`
- **Method**: `POST`
- **Authentication**: None (public endpoint)
- **Rate Limit**: 5 requests per minute per IP

### Functionality
1. Validates invite code existence and expiration
2. Checks for duplicate email or username
3. Hashes password using bcrypt
4. Creates user record in Supabase
5. Generates 16-character recovery key
6. Marks invite as redeemed with user ID
7. Returns JWT token for immediate login

### Request Parameters

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `username` | string | Yes | Unique username (3-32 characters) |
| `displayName` | string | Yes | User's display name (shown in profile) |
| `email` | string | Yes | Valid email address |
| `password` | string | Yes | Min 8 characters |
| `inviteCode` | string | Yes | Valid 16-char invite code |
| `profilePicture` | string | No | Base64-encoded JPEG image (max 2MB) |

### Response Fields

```json
{
  "message": "Account created successfully",
  "token": "JWT_TOKEN_HERE",
  "user": {
    "id": "uuid",
    "username": "johndoe",
    "displayName": "John Doe",
    "email": "john@example.com",
    "isProUser": false,
    "hasAdminPrivileges": false
  },
  "recoveryKey": "16_CHARACTER_KEY"
}
```

## 2. Login Endpoint

### Overview
The Login endpoint handles three distinct operations: traditional username/password authentication, handoff code generation for secure cross-domain token transfer, and handoff code consumption/exchange for session establishment.

### Endpoint Details
- **URL**: `/login`
- **Method**: `POST`
- **Authentication**: None for login; Bearer token for handoff creation
- **Rate Limit**: 10 requests per minute per IP (prevents brute force)

### Functionality
**Traditional Login Flow**:
1. Accepts username or email and password
2. Queries user database by username or email field
3. Compares provided password with bcrypt hash
4. Generates JWT token valid for 30 days
5. Creates one-time handoff code (expires in 60 seconds)
6. Returns token and user metadata

**Handoff Generation Flow**:
1. Verifies Authorization header contains valid JWT
2. Extracts user ID from token payload
3. Generates 32-character random handoff code
4. Stores code with user IP, user agent, and expiration
5. Returns code for cross-domain exchange

**Handoff Exchange Flow**:
1. Accepts handoff code in request body
2. Validates code exists and hasn't expired
3. Verifies requesting IP matches original
4. Consumes code (marks as used, prevents reuse)
5. Returns new JWT token and user data

### Request Parameters

#### Traditional Login
```json
{
  "username": "johndoe",
  "password": "SecurePass123!"
}
```

#### Create Handoff Code
```json
{
  "action": "create"
}
```
Headers must include: `Authorization: Bearer YOUR_TOKEN`

#### Exchange Handoff Code
```json
{
  "code": "32_CHARACTER_HANDOFF_CODE"
}
```
Or with explicit action:
```json
{
  "action": "exchange",
  "handoffCode": "32_CHARACTER_HANDOFF_CODE"
}
```

### Response Fields (Traditional Login)

```json
{
  "message": "Login successful",
  "token": "JWT_TOKEN_HERE",
  "handoffCode": "32_CHAR_ONE_TIME_CODE",
  "user": {
    "id": "uuid",
    "username": "johndoe",
    "displayName": "John Doe",
    "email": "john@example.com",
    "hasAdminPrivileges": false,
    "isPlusUser": false,
    "profilePicture": "https://..."
  }
}
```

### Response Fields (Handoff Exchange)

```json
{
  "message": "Handoff successful",
  "token": "NEW_JWT_TOKEN",
  "user": {
    "id": "uuid",
    "username": "johndoe",
    "displayName": "John Doe",
    "email": "john@example.com",
    "hasAdminPrivileges": false,
    "isPlusUser": false,
    "profilePicture": "https://..."
  }
}
```

## 3. Password Recovery Endpoint

### Overview
The Password Recovery endpoint allows users to reset their password using their registered email and 16-character recovery key. This endpoint is critical for account access restoration when passwords are forgotten.

### Endpoint Details
- **URL**: `/auth?action=forgot-password`
- **Method**: `POST`
- **Authentication**: None (recovery key serves as authentication)
- **Rate Limit**: 3 requests per hour per email (brute-force protection)

### Functionality
1. Validates email exists in database
2. Verifies recovery key matches stored key
3. If new password provided: hashes and updates password
4. Generates JWT token for immediate login
5. Logs recovery attempt for security audit
6. Returns success message with new token

### Request Parameters

```json
{
  "email": "john@example.com",
  "recoveryKey": "16_CHARACTER_KEY",
  "newPassword": "NewSecurePass123!"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | Account's registered email |
| `recoveryKey` | string | Yes | 16-character key from signup |
| `newPassword` | string | No | Min 8 characters. If omitted, only validates key |

### Response Fields

```json
{
  "message": "Password updated successfully",
  "token": "NEW_JWT_TOKEN",
  "timestamp": "2025-02-04T10:30:00Z"
}
```

Or if only validating (no new password):
```json
{
  "verified": true,
  "message": "Recovery key valid",
  "timestamp": "2025-02-04T10:30:00Z"
}
```

## 4. Admin Account Recovery

### Overview
The Admin Account Recovery endpoint is a critical security tool that allows administrators to retrieve the recovery key of any user for emergency account restoration. This is used when a user cannot access their account and regular recovery methods fail.

### Endpoint Details
- **URL**: `/auth?action=admin-recovery`
- **Method**: `POST`
- **Authentication**: Required (Bearer token with admin privileges)
- **Authorization**: Admin-only endpoint

### Functionality
1. Verifies Authorization header contains valid JWT
2. Validates user has admin privileges
3. Queries user database by email AND username
4. Returns complete user profile including recovery key
5. Logs admin recovery request with timestamp
6. Returns all necessary data for account restoration

### Request Parameters

```json
{
  "email": "target@example.com",
  "username": "targetuser"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | Target user's email |
| `username` | string | Yes | Target user's username |

### Response Fields

```json
    "displayName": "Target User",
```

### Error Responses

| Status | Error | Cause |
|--------|-------|-------|
| 400 | `Both email and username are required` | Missing email or username |
| 401 | `Authentication token required` | No Authorization header |
| 401 | `Invalid or expired token` | Token invalid or expired |
| 403 | `Admin privileges required` | User doesn't have admin status |
| 404 | `User not found` | No user with email AND username combo |
| 500 | `Internal server error` | Database connection failure |

### Security Considerations
- This endpoint requires both email AND username match (prevents targeting wrong users)
- All recovery attempts are logged with admin ID and timestamp
- Recovery keys should never be transmitted insecurely
- Recommend using this only over HTTPS
- Consider requiring additional auth factor for sensitive operations

## 5. Profile Endpoint

### Overview
The Profile endpoint provides GET, PUT, and DELETE operations for user account management. Users can retrieve their profile, update personal information, change passwords, generate recovery keys, update profile pictures, and delete their accounts.

### Endpoint Details
- **URL**: `/profile`
- **Methods**: `GET`, `PUT`, `DELETE`
- **Authentication**: Required (Bearer token)

### GET: Retrieve Profile

#### Functionality
1. Validates JWT token from Authorization header
2. Queries user record by token's user ID
3. Returns complete profile with tier status
4. Exposes recovery key to authenticated user

#### Response Fields

```json
{
  "user": {
    "id": "uuid",
    "username": "johndoe",
    "displayName": "John Doe",
    "email": "john@example.com",
    "profilePicture": "https://...",
    "recoveryKey": "16_CHAR_KEY",
    "hasAdminPrivileges": false,
    "isProUser": false,
    "isPlusUser": false,
    "plusExpiry": null,
    "createdAt": "2025-01-01T00:00:00Z",
    "updatedAt": "2025-02-01T12:30:00Z"
  }
}
```

### PUT: Update Profile

#### Functionality
1. Validates JWT token
2. Parses update request body
3. Validates username uniqueness if changed
4. Verifies current password before password change
5. Hashes new password using bcrypt
6. Uploads profile picture to Supabase storage if provided
7. Generates new recovery key if requested
8. Updates all fields in database
9. Returns updated profile

#### Request Parameters

```json
{
  "username": "newusername",
  "displayName": "New Display Name",
  "currentPassword": "CurrentPass123!",
  "newPassword": "NewPass123!",
  "generateNewRecoveryKey": true,
  "profilePicture": "data:image/jpeg;base64,..."
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `username` | string | No | New username if changing |
| `displayName` | string | No | New display name |
| `currentPassword` | string | No | Required if changing password or recovery key |
| `newPassword` | string | No | New password (min 8 chars), requires currentPassword |
| `generateNewRecoveryKey` | boolean | No | Generate new recovery key, requires currentPassword |
| `profilePicture` | string | No | Base64 JPEG image data URL |

#### Response Fields

```json
{
  "message": "Profile updated successfully",
  "user": {
    "id": "uuid",
    "username": "newusername",
    "displayName": "New Display Name",
    "email": "john@example.com",
    "profilePicture": "https://...",
    "recoveryKey": "new_recovery_key",
    "hasAdminPrivileges": false,
    "isProUser": false,
    "isPlusUser": false,
    "plusExpiry": null,
    "createdAt": "2025-01-01T00:00:00Z",
    "updatedAt": "2025-02-04T10:30:00Z"
  }
}
```

### DELETE: Delete Account

#### Functionality
1. Validates JWT token
2. Verifies current password in request body
3. Deletes user record and all associated data
4. Removes profile pictures from storage
5. Returns success confirmation

#### Request Parameters

```json
{
  "currentPassword": "CurrentPass123!"
}
```

#### Response

```json
{
  "message": "Account deleted successfully",
  "timestamp": "2025-02-04T10:30:00Z"
```

## 7. Search Endpoint

### Overview
The Search endpoint provides intelligent content discovery through a hybrid approach combining Fuse.js fuzzy string matching with optional AI fallback for complex queries. It searches through educational materials, posts, and documents with content safety filtering.

### Endpoint Details
- **URL**: `/search`
- **Method**: `POST`
- **Authentication**: Optional (better results with token)
- **Rate Limit**: 30 requests per minute

### Functionality
1. Validates search query for length and appropriateness
2. Filters unsafe/gibberish content
3. Performs Fuse.js fuzzy search on indexed content
4. If useAI enabled and results below threshold: queries AI
5. Deduplicates results
6. Ranks by relevance score
7. Returns paginated results

### Request Parameters

```json
{
  "query": "operating system concepts",
  "useAI": true,
  "threshold": 0.4,
  "limit": 10,
  "offset": 0
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `query` | string | Yes | Search term (1-200 characters) |
| `useAI` | boolean | No | Enable AI fallback (default: false) |
| `threshold` | number | No | Minimum relevance score 0-1 (default: 0.5) |
| `limit` | number | No | Results per page (default: 10, max: 50) |
| `offset` | number | No | Pagination offset (default: 0) |

### Response Fields

```json
{
  "success": true,
  "query": "operating system",
```

## Global HTTP Error Reference

This section consolidates all error responses across all API endpoints. Use this as a single reference for understanding error codes and how to handle them.

### HTTP Status Codes and Meanings

| Code | Name | Applicable To | Action |
|------|------|---------------|--------|
| **200** | OK | All endpoints | Request succeeded, proceed normally |
| **201** | Created | Signup, Create Invites, Create Form | Resource created successfully |
| **400** | Bad Request | All endpoints | Fix invalid input - missing fields, wrong types, validation failures |
| **401** | Unauthorized | Auth endpoints, Protected endpoints | Invalid/missing token, wrong credentials, expired recovery key |
| **403** | Forbidden | Admin endpoints | Lack admin privileges, permission denied |
| **404** | Not Found | Profile, Invites, CDN, Forms | Resource doesn't exist (user, invite, file, form) |
| **405** | Method Not Allowed | Auth endpoints | Wrong HTTP method (GET instead of POST) |
| **409** | Conflict | Signup, Invites | Resource conflict - duplicate username, already redeemed invite |
| **413** | Payload Too Large | Features (upload), CDN | File/body exceeds size limit |
| **429** | Too Many Requests | All endpoints | Rate limit exceeded, exponential backoff required |
| **500** | Internal Server Error | All endpoints | Server-side failure - usually database issues |
| **503** | Service Unavailable | Health, Search, Features | External service down (Supabase, OpenRouter, GitHub) |

### Endpoint-Specific Errors

**Signup:** Missing fields, invalid email, weak password, invalid/expired invite, duplicate username/email, rate limited  
**Login:** Missing credentials, invalid credentials, invalid/expired token, handoff code issues, rate limited  
**Password Recovery:** Missing email/key, user not found, invalid recovery key, rate limited  
**Admin Recovery:** Missing token/user info, invalid token, no admin privileges, user not found, rate limited  
**Profile:** Invalid fields, weak password, no auth, wrong password, cannot modify others, user not found  
**Chat:** Missing query, invalid model, inappropriate content, no auth, rate limited, AI service issues  
**Search:** Missing query, query length issues, invalid threshold, inappropriate content, rate limited  
**Features:** Missing action, invalid action, missing parameters, file too large, no auth, insufficient permissions  
**Invites:** Invalid code format, missing parameters, no auth, no admin privileges, code not found, already redeemed  
**CDN:** Missing path, file too large, invalid path, no auth, no admin privileges, file not found, already exists, rate limited  

For detailed error responses and solutions, refer to the HTTP Status Codes section above. All endpoints follow standard HTTP error codes (400, 401, 403, 404, 429, 500, 503).

#### **Health Check Endpoint (GET /health)**
**Status codes:** 200 (healthy), 503 (unavailable)  
**Errors:** Service down, components unavailable  
Use this endpoint to monitor API health and component status. Returns detailed latency metrics and error tracking.

### Error Handling Best Practices

**For 401/403 Errors**:
- Check token exists in Authorization header
- Verify token hasn't expired (30-day expiration)
- Confirm user has required admin/Plus privileges
- Regenerate token by logging in again

**For 429 Errors**:
- Implement exponential backoff: retry with increasing delays
- Check `Retry-After` header if provided
- Typical limits: 5-50 requests per minute per endpoint
- Cache results when possible to reduce requests

**For 500/503 Errors**:
- These are temporary server issues, retry with backoff
- Check API status page: https://materioa.vercel.app/api/v2/health
- Contact support if errors persist for 30+ minutes
- Implement circuit breaker pattern for resilience

**For 400 Errors**:
- Validate all required fields before sending request
- Check data types match schema (string vs number)
- Verify length constraints (usernames, passwords, etc.)
- Ensure proper encoding for special characters

## Security Best Practices

### 1. Token Management
- **Never hardcode tokens** in client-side code
- Store tokens in **secure, httpOnly cookies** or encrypted localStorage
- Include `Authorization: Bearer <TOKEN>` in all authenticated requests
- Tokens expire after 30 days; implement refresh logic
- Use HTTPS only for all API requests

### 2. Handoff Codes
- Exchange handoff codes **immediately** after login (60-second expiration)
- Use for secure cross-domain session transfer
- One-time use only - each code can be consumed once
- Store handoff code in memory, not localStorage
- Verify requesting IP matches original login IP

### 3. Recovery Keys
- Generate 16-character recovery keys during signup
- **Never** expose recovery keys in logs or error messages
- Advise users to store keys **offline** in secure location
- Only recovery method if password is forgotten
- Consider implementing time-based access restrictions

### 4. Password Security
- Enforce **minimum 8 characters**
- Recommend mixed case, numbers, special characters
- Hash all passwords with bcrypt (minimum 10 rounds)
- Never transmit or log plaintext passwords
- Implement password strength indicators

### 5. API Security
- **CORS is enforced** - only whitelisted origins accepted
- All admin operations require authentication + privileges
- Admin endpoints verified server-side (never client-side)
- Rate limiting prevents brute-force attacks
- Content safety filters detect inappropriate queries

### 6. Data Privacy
- Email addresses are private - never display publicly
- Profile pictures uploaded to secure storage (Supabase)
- Never log sensitive data (passwords, tokens, recovery keys)
- Implement data retention policies for inactive accounts
- GDPR compliant account deletion available

### 7. Admin Operations
- Admin tokens never exposed to frontend
- Admin privileges verified on every request
- Admin recovery requires both email AND username
- Log all admin actions with timestamp/admin ID
- Implement admin action audit trail

### 8. Third-party Integrations
- Google Drive: OAuth2 with minimal scope
- GitHub CDN: Atomic commits prevent race conditions
- OpenRouter AI: API key never transmitted to client
- Razorpay: Payment processing PCI-DSS compliant

### 9. File Uploads
- Max file size: 6 MB
- Validate file types server-side
- Scan for malware before storage
- Store in isolated cloud buckets
- Implement virus scanning for user uploads

### 10. Monitoring & Logging
- Monitor failed authentication attempts
- Alert on suspicious admin activity
- Log all API errors for debugging
- Track rate limit violations
- Monitor for DDoS patterns
